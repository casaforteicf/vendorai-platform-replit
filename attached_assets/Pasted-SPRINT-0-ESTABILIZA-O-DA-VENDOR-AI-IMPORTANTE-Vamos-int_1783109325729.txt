SPRINT 0 — ESTABILIZAÇÃO DA VENDOR.AI

IMPORTANTE

Vamos interromper temporariamente a criação de novas funcionalidades.

O objetivo agora é transformar o que já foi desenvolvido em uma base sólida para produção.

Utilize como referência o relatório técnico de arquitetura gerado anteriormente.

Priorizar exclusivamente os itens P0 e P1.

Não criar novos módulos.

Não alterar a experiência do usuário.

Não adicionar novas telas.

Não iniciar integrações com IA antes da conclusão deste Sprint.

====================================================
OBJETIVO
====================================================

Preparar a Vendor.ai para suportar IA real, usuários reais e múltiplos tenants.

====================================================
P0-001 — AQM REAL
====================================================

Remover toda dependência de MOCK_PROJECT_CONTEXT.

Todos os Engines devem consumir exclusivamente:

activeProject

activeObjects

activeMaterials

activeRelationships

activeDNA

obtidos através do ProjectContext.

Eliminar qualquer fluxo que gere recomendações usando dados fictícios.

====================================================
P0-002 — OPENAPI
====================================================

Todas as rotas do Workspace Arquitetura devem seguir o padrão Contract First.

Adicionar ao OpenAPI:

ArqProject

ArqObject

ArqMaterial

ArqComponent

AieSnapshot

PromptVariation

RenderJob

RenderReview

Executar novamente o codegen.

Eliminar fetch() manual.

Utilizar apenas hooks gerados.

====================================================
P0-003 — WORKSPACE CONTEXT
====================================================

Remover valores mockados.

WorkspaceContext deve utilizar:

tenantId

workspaceId

userId

teamId

permissions

organizationId

obtidos da autenticação da Vendor.ai.

Nenhum valor hardcoded deve permanecer.
