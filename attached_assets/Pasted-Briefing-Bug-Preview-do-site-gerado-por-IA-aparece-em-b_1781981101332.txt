Briefing — Bug: Preview do site gerado por IA aparece em branco (mesmo com status "Pronto")

Problema observado

Na tela /configuracoes → aba Site → Gerador IA → sub-aba Preview: o status exibido é "Pronto" (indicando que a geração terminou com sucesso), mas a área de preview abaixo fica completamente em branco — sem conteúdo, sem mensagem de erro, sem placeholder.

Contexto relevante

O gerador de sites foi recentemente migrado para usar Claude (claude-sonnet-4-6) como provider principal, com fallback para OpenAI — confirmado por log mostrando provider: "anthropic". Esse bug provavelmente surgiu junto com essa mudança.

Causa provável

O formato de resposta da API da Anthropic é estruturalmente diferente do formato da OpenAI (blocos de conteúdo content: [{type: "text", text: "..."}], possivelmente com markdown fencing tipo ```html ... ``` envolvendo o HTML gerado). Se o código que processa a resposta do gerador de sites foi escrito originalmente pensando no formato de resposta da OpenAI e não foi ajustado para o formato da Anthropic, o parsing pode estar:


Não encontrando o campo de texto corretamente na resposta da Anthropic (extraindo string vazia ou undefined).
Não removendo o markdown fencing ( ```html no início/fim) se o Claude envolver o HTML em bloco de código, deixando o conteúdo salvo como inválido para renderização.
Salvando com sucesso um conteúdo vazio/malformado no banco, e o status de "Pronto" está sendo setado apenas com base em "a chamada à API não retornou erro", não em "o conteúdo extraído é válido".


Onde investigar


Função/serviço responsável por processar a resposta do gerador de sites com IA (provavelmente algo como generateSiteWithAI() ou siteGeneratorService.ts).
Conferir como o código extrai o texto da resposta — deve ser algo como response.content[0].text para Anthropic, diferente de response.choices[0].message.content da OpenAI.
Conferir se há lógica de remoção de markdown fencing (html / ) antes de salvar o HTML gerado.
Conferir nos logs do backend (ou no banco) o que de fato foi salvo no campo de conteúdo do site gerado — provavelmente está vazio, null, ou contém só os ``` sem o HTML real.


Correção sugerida


Ajustar a extração de conteúdo da resposta para o formato correto da Anthropic SDK (message.content é um array de blocos; concatenar todos os blocos do tipo text).
Adicionar uma etapa de limpeza: remover fences de markdown ( ```html, ```) do início/fim do texto extraído antes de salvar/renderizar.
Não marcar o site como "Pronto" se o conteúdo extraído estiver vazio ou não passar numa validação básica (ex: checar se contém pelo menos uma tag <html ou <!DOCTYPE). Se inválido, marcar como erro e idealmente tentar o fallback OpenAI automaticamente, ou expor mensagem de erro clara para o usuário em vez de "Pronto" com tela em branco.
Validar também se o componente de Preview no frontend está, de fato, renderizando o campo certo do site (não é só problema de backend — confirmar que o frontend busca o campo correto da API).


Teste de validação


Gerar um novo site de teste pelo "Gerador IA".
Conferir no log do backend qual provider respondeu (Claude ou fallback OpenAI) e o conteúdo bruto da resposta.
Confirmar que o Preview mostra o site renderizado corretamente, não em branco.
Forçar um cenário de resposta inválida/vazia (se possível simular) e confirmar que o sistema não marca como "Pronto" — deve mostrar erro ou tentar fallback.
