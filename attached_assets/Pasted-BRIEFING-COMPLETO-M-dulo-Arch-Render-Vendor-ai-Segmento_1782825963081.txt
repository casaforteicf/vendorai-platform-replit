VISÃO GERAL DO MÓDULO
O módulo Arch/Render permite ao usuário (arquiteto, construtora, decorador) trabalhar em cima de um projeto 3D já modelado, aplicando:
Materiais/texturas em superfícies específicas (paredes, telhado, esquadrias, piso, móveis, decorações, todos itens do projeto)
Configurações de iluminação (Manhã, Tarde, Golden hour, Noturno)
Ângulos de câmera (Frontal, 45°, Lateral Esquerda, Lateral Direita, Ampla, Aérea)
Opção de decoração geradas por IA, em estilos predefinidos — sem alterar o projeto real
Regra de ouro do módulo: o render do projeto NUNCA pode alterar geometria, proporções ou posicionamento de elementos estruturais. Tudo que é avaliação real do projeto (não sugestão) deve preservar 100% a estrutura original. Apenas luz, material/textura e ângulo de câmera podem mudar.

PRIORIDADE 1 — Corrigir erro 500 (bloqueador atual)
Sintoma
Console: Failed to load resource: /api/arch/render — status 500
Console: Erro no render: Error: Erro 500
Diagnóstico obrigatório antes de qualquer correção
1. Acessar logs do servidor no endpoint POST /api/arch/render
2. Capturar o stack trace completo da exceção
3. Identificar se o erro é:
   a) Validação de payload (formato mudou e backend não trata)
   b) Falha na chamada à API de geração de imagem (timeout, credencial, rate limit)
   c) Erro ao processar/compor a imagem resultante
Correção
1. Adicionar try/catch estruturado em todo o fluxo de /api/arch/render
2. Logar o payload recebido e o ponto exato da falha
3. Retornar erro específico ao frontend:
   { success: false, error: "<mensagem real, não genérica>" }
4. Frontend deve exibir essa mensagem real no lugar de "Erro 500"
5. Adicionar validação de schema no payload de entrada (rejeitar requisições 
   malformadas antes de processar, com erro 400 claro)

PRIORIDADE 2 — Garantir que o render não altera estrutura
Causa raiz mais provável
Se a API de geração de imagem usada atualmente for text-to-image puro (gera a cena do zero a cada chamada), é estruturalmente impossível garantir preservação só com instruções de prompt — a IA pode reinterpretar livremente.
Ação obrigatória
1. Identificar qual provider/API está em uso hoje no endpoint de render
2. Se for text-to-image puro → TROCAR a abordagem para:
   - img2img com a imagem-base do projeto + strength/denoise baixo (0.2–0.4), OU
   - inpainting restrito às máscaras de superfície (Prioridade 3)
3. Se já usa img2img/inpainting → apenas ajustar o prompt de sistema:

   "Preserve exatamente a estrutura, proporções, geometria e posicionamento de 
   todos os elementos da imagem original. Não adicione, remova ou reposicione 
   paredes, janelas, portas, telhado ou qualquer elemento estrutural. Aplique 
   apenas: iluminação conforme especificado, e material/textura nas superfícies 
   indicadas pelas máscaras fornecidas."

PRIORIDADE 3 — Sistema de superfícies individuais com material independente
Modelo de dados
Cada superfície é um registro individual — duas paredes da mesma categoria podem ter materiais diferentes simultaneamente (ex: parede frontal esquerda em madeira, parede frontal direita em pedra).
sql
CREATE TABLE IF NOT EXISTS render_surfaces (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  project_id uuid REFERENCES arch_projects(id),
  category text NOT NULL, -- parede | telhado | esquadria | piso | movel | outro
  label text NOT NULL,    -- ex: "Parede frontal esquerda", "Telhado principal"
  mask_path text NOT NULL, -- PNG com área branca = região da superfície
  display_order int DEFAULT 0,
  created_at timestamptz DEFAULT now()
);

CREATE TABLE IF NOT EXISTS render_surface_materials (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  surface_id uuid REFERENCES render_surfaces(id),
  material_id uuid REFERENCES materials(id), -- tabela já existente: Madeira, MDF, Pedra, Ferro, Cerâmica, Concreto, Aço
  applied_at timestamptz DEFAULT now(),
  applied_by uuid REFERENCES users(id)
);
Geração inicial das máscaras (uma vez, na criação do projeto)
1. Ao criar/importar um projeto, rodar segmentação automática (ex: Segment 
   Anything Model — SAM) para identificar regiões candidatas
2. Classificar automaticamente por categoria sugerida
3. Salvar cada região como registro em render_surfaces com seu mask_path
4. Permitir revisão manual: usuário pode mesclar, dividir ou renomear superfícies
Frontend — seleção e aplicação de material
1. Overlay clicável sobre a imagem do projeto
2. Hover destaca a superfície sob o cursor
3. Clique abre painel lateral:
   - Nome da superfície (editável)
   - Material atual aplicado
   - Lista de materiais disponíveis
   - Botão "Aplicar material"
4. Cada superfície guarda seu material de forma independente
Backend — render com múltiplos materiais
POST /api/arch/render
body: {
  project_id,
  surfaces: [
    { surface_id, material_id },
    { surface_id, material_id },
    ...
  ],
  lighting: "noturno",
  angle: "lateral_esquerda"
}

Processamento:
1. Para cada surface: carregar mask_path, aplicar inpainting/texture mapping 
   com o material correspondente, restrito à área da máscara
2. Compor resultado final combinando todas as superfícies + áreas não mascaradas
3. Aplicar iluminação por último (não deve alterar geometria)
4. Retornar URL da imagem final

PRIORIDADE 4 — Rotação de câmera 3D (vistas laterais)
Contexto
A imagem é baseada em modelo 3D real já existente no sistema. A rotação deve mover a câmera dentro do motor 3D — não gerar via IA. Isso garante fidelidade estrutural por natureza técnica.
Ajuste nas opções de ângulo
Atual:  [Frontal] [45°] [Lateral] [Ampla] [Aérea]
Novo:   [Frontal] [45°] [Lateral Esq.] [Lateral Dir.] [Ampla] [Aérea]

Lateral esquerda = rotação -90° em torno do eixo Y a partir do frontal
Lateral direita  = rotação +90° em torno do eixo Y a partir do frontal
Comportamento — preservar configurações ao trocar ângulo
Ao mudar de ângulo, MANTER automaticamente:
- Materiais já aplicados por superfície (render_surface_materials)
- Iluminação selecionada (Manhã/Tarde/Golden/Noturno)
- Qualquer pós-processamento já configurado
Re-renderizar a cena na nova posição de câmera SEM resetar nada.
Estado no frontend
javascript
const [renderConfig, setRenderConfig] = useState({
  surfaces: [],      // materiais já aplicados
  lighting: 'noturno',
  angle: 'frontal'
});

function handleAngleChange(newAngle) {
  setRenderConfig(prev => ({ ...prev, angle: newAngle }));
  triggerRender({ ...renderConfig, angle: newAngle });
}

PRIORIDADE 5 — Card de Sugestões de Decoração com IA
Importante: isolado do projeto real
Esse card gera imagens de referência separadas — nunca substitui ou altera o render do projeto. Aqui, diferente das prioridades acima, a IA PODE adicionar móveis e elementos decorativos, porque é só inspiração visual.
UI do card
┌─────────────────────────────────┐
│ ✨ Sugestões de Decoração        │
├─────────────────────────────────┤
│ Estilo:                          │
│ [Minimalista] [Atemporal]        │
│ [Provençal]   [Neoclássico]      │
│ [Moderno]                        │
│                                   │
│ [ Gerar sugestão ]                │
└─────────────────────────────────┘
Comportamento
1. Usuário seleciona 1 estilo
2. Clica "Gerar sugestão"
3. Sistema gera imagem separada usando o render atual como referência de ambiente
4. Resultado abre em modal:
   - Imagem da sugestão
   - "Salvar como referência" (galeria do projeto, não aplica no render)
   - "Descartar"
   - "Gerar outra variação"
Características de prompt por estilo
minimalista:  linhas limpas, poucos elementos, paleta neutra, mobiliário funcional
atemporal:    elementos clássicos discretos, paleta equilibrada, sem tendências passageiras
provençal:    estilo rústico francês, madeira envelhecida, tons pastéis, flores, ferro forjado
neoclássico:  colunas, simetria, tons claros, elementos ornamentais sóbrios
moderno:      formas geométricas, materiais industriais, paleta contrastante, tecnologia integrada
Backend
POST /api/arch/suggestions
body: { project_id, style: 'minimalista' | 'atemporal' | 'provencal' | 'neoclassico' | 'moderno' }

CREATE TABLE IF NOT EXISTS arch_suggestions (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  project_id uuid REFERENCES arch_projects(id),
  style text NOT NULL,
  image_url text NOT NULL,
  saved boolean DEFAULT false,
  created_at timestamptz DEFAULT now()
);
