What & Why
Criar um tenant de demonstração isolado para o Vendor.ai, com login demo/demo, populado com dados fictícios realistas em todos os módulos (leads, negócios, orçamentos, conversas, estoque, agenda, dashboard). Serve para apresentações comerciais e demos com prospects sem misturar com dados reais de clientes.

Done looks like
Login demo/demo funciona e leva ao tenant de demonstração
Dashboard exibe 7 cards com dados reais (pipeline, ganhos, orçamentos, tipos de cliente, dores, churn, leads quentes)
Leads: mix de estágios (novo, qualificado, proposta, negociação, ganho, perdido, churn risk alto)
Negócios: distribuídos pelas etapas do Kanban
Orçamentos: rascunho, enviado, aceito, rejeitado, incluindo um recorrente
Conversas: histórico de mensagens simuladas (WhatsApp/Instagram)
Estoque: catálogo com produtos fictícios (materiais de construção)
Agenda: compromissos futuros e passados
Tenant isolado de integrações reais (sem WhatsApp, Instagram, Google Calendar, Asaas conectados)
Ações de envio real são simuladas (no-op) neste tenant
Job de reset automático diário restaura dados ao estado inicial
Rate limiting no login demo/demo
Out of scope
Criar UI dedicada para demo (usar a mesma do frontend)
Modificar o site institucional para divulgar o demo (aqui é só o backend)
Implementar billing real para o demo tenant
Steps
Schema: adicionar flags e plano demo — Garantir que tenants tem is_demo, demo_seeded, demo_expires_at, e que plans tem um plano "enterprise" fictício para demo. Verificar que já existem.

Seed do demo tenant — Criar script de seed que:

Cria tenant demo com plano enterprise
Cria usuário demo/demo com tenant_admin
Popula leads (~20), negócios (~10), orçamentos (~6), conversas (~8), produtos (~10), estoque (~5), agenda (~4), atividades (~8)
Marca tenant como demo_seeded = true
Simulação de integrações — Modificar rotas de WhatsApp, Instagram, e-mail e agendamento para detectar tenant.is_demo e executar no-op (salvar no banco como simulado, sem chamar APIs externas).

Job de reset diário — Adicionar cron job no scheduler que:

Encontra todos os tenants is_demo = true
Apaga dados modificados e re-seed com estado inicial
Roda de madrugada
Rate limiting no login demo — Adicionar rate limiting no endpoint de login para credenciais demo/demo (max 5 tentativas/min, 20/hora).

Testes e validação — Rodar typecheck e tests. Logar com demo/demo e confirmar que todos os dados aparecem corretamente.
