Briefing: Fechamento Automático de Deal (Trigger "Ganho")
Objetivo
Quando um negócio (deal) é marcado como "Ganho" no Kanban do CRM, o sistema deve automaticamente:
Identificar o tipo de contrato correto
Gerar o contrato preenchido
Enviar para assinatura digital via ZapSign
Enviar o convite de onboarding ao cliente, por WhatsApp e E-mail
Tudo isso sem intervenção manual do vendedor/admin.
Fluxo completo
1. Trigger: status do deal muda para "Ganho"
Adicionar um hook/listener no backend que dispara quando deals.status é atualizado para ganho (seja via drag-and-drop no Kanban ou via API)
O listener deve carregar os dados completos do deal: lead vinculado, valor, produtos/serviços, e se há um parceiro/reseller vinculado a esse deal/tenant
2. Decisão do tipo de contrato
Lógica condicional:
Se o deal/tenant tem um parceiro/reseller vinculado → usar o template de contrato 3 partes (Vendor.ai + Parceiro + Cliente)
Se não tem parceiro vinculado → usar o template de contrato 2 partes (venda direta Vendor.ai + Cliente)
Verificar no schema atual se já existe um campo tipo deals.partner_id ou tenants.partner_id que indique isso. Se não existir, será necessário adicionar essa relação ao modelo de dados antes de implementar a lógica.
3. Geração do contrato
Usar os templates .docx já existentes (contrato 2 partes e contrato 3 partes)
Preencher automaticamente os campos com os dados do deal: nome do cliente, CNPJ/CPF (se disponível), valor do negócio, produtos/serviços contratados, data
Gerar o arquivo final (PDF ou DOCX, conforme o que o ZapSign aceitar melhor — geralmente PDF)
4. Envio automático para assinatura via ZapSign
Integrar com a API do ZapSign para criar o documento e enviar para assinatura
Signatários:
Cliente (e-mail/telefone do lead)
Parceiro, se aplicável (contrato 3 partes)
Vendor.ai (Marcos ou representante padrão configurado)
Salvar o document_id retornado pelo ZapSign associado ao deal, para rastrear status de assinatura depois (pendente, assinado, recusado)
5. Envio do convite de onboarding (WhatsApp + E-mail)
Disparar em paralelo (não depende da assinatura do contrato ter sido concluída):
WhatsApp: enviar mensagem via Meta Cloud API com o link de acesso ao wizard de onboarding (16 passos)
E-mail: enviar e-mail (via Resend, conforme stack já configurada) com o mesmo link, mais informações de boas-vindas
Conteúdo sugerido da mensagem:
Boas-vindas
Link único de onboarding (token de acesso, vinculado ao tenant recém-criado)
Aviso de que o contrato foi enviado para assinatura separadamente (se aplicável)
6. Criação do tenant
Se o tenant ainda não existir para esse cliente, criar automaticamente neste momento (status inicial: aguardando onboarding)
Vincular o partner_id ao tenant, se aplicável, para que o billing split (50/50) funcione corretamente depois
Pontos de atenção / validações necessárias
Idempotência: se o deal for movido para "Ganho" mais de uma vez (ex: por engano, movido de volta e novamente para Ganho), o sistema NÃO deve gerar contrato duplicado nem reenviar onboarding duplicado. Adicionar uma flag deals.closure_triggered_at para evitar reprocessamento.
Dados obrigatórios faltando: se o lead não tiver e-mail ou telefone válido, ou CNPJ/CPF necessário para o contrato, o sistema deve:
Não falhar silenciosamente
Notificar o admin (ex: notificação no Dashboard ou e-mail interno) que a automação não pôde ser concluída e por quê
Permitir completar manualmente os dados faltantes e disparar novamente
Falha na API do ZapSign: se a chamada falhar, registrar erro e permitir reenvio manual pela interface (não travar o fluxo de onboarding por causa disso)
Status visível no Kanban/Deal: o card do deal "Ganho" deve mostrar visualmente o status dessa automação:
Contrato: Gerando / Enviado para assinatura / Assinado / Erro
Onboarding: Convite enviado / Em andamento / Concluído
Resultado esperado
Ao arrastar um deal para "Ganho" no Kanban, em poucos segundos:
O contrato correto (2 ou 3 partes) é gerado e enviado para assinatura no ZapSign
O cliente recebe convite de onboarding por WhatsApp e e-mail simultaneamente
O admin consegue acompanhar o status de tudo isso diretamente no card do deal, sem precisar fazer nada manualmente
