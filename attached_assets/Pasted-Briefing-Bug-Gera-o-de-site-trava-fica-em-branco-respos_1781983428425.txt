Briefing — Bug: Geração de site trava/fica em branco (resposta da IA truncada por max_tokens)

Problema observado

Mesmo após a correção do extractHtml() (que agora pega o último </html> em vez do primeiro), o preview do Gerador de Sites com IA continua aparecendo em branco/travado, com status "Pronto".

Inspecionando o HTML gerado num caso real, o conteúdo termina abruptamente no meio de uma regra CSS, sem nunca chegar no <body> nem no </html> de fechamento. Ou seja: a resposta da IA está sendo cortada antes de terminar, não é mais um problema de qual </html> escolher — não existe nenhum </html> na resposta.

Causa provável

A chamada à API da Anthropic (claude-sonnet-4-6) para gerar o site provavelmente está configurada com um max_tokens baixo demais para o tamanho real do HTML que está sendo pedido (landing page completa, com CSS extenso, várias seções, animações). Quando a geração atinge esse limite, a Anthropic API corta a resposta no meio e retorna stop_reason: "max_tokens" em vez de "end_turn" — mas o código aparentemente não está checando esse campo, então trata a resposta cortada como se estivesse completa e marca o status como "Pronto".

Onde investigar


Localizar a chamada à API Anthropic no serviço de geração de site (mesmo arquivo do extractHtml(), provavelmente site_generator.ts).
Conferir o valor de max_tokens passado na chamada client.messages.create({ ..., max_tokens: ??? }).
Conferir se o código olha o campo stop_reason da resposta antes de considerar a geração bem-sucedida.


Correção sugerida


Aumentar o max_tokens da chamada para um valor generoso o suficiente para uma landing page completa (HTML + CSS + JS) — claude-sonnet-4-6 suporta até 64.000 tokens de saída na API síncrona. Um valor entre 12.000 e 20.000 deve cobrir a maioria dos sites gerados sem desperdiçar limite à toa; ajustar com base no tamanho real observado nos sites já gerados.
Checar stop_reason na resposta: se vier "max_tokens" (cortado por limite) em vez de "end_turn" (terminou naturalmente), não marcar o site como "Pronto". Nesse caso:

Tentar novamente com max_tokens maior, ou
Marcar como erro e avisar o usuário, ou
(mais robusto, mas mais trabalho) implementar continuação: pedir pra IA continuar de onde parou e concatenar.



Manter a validação de conteúdo já sugerida no briefing anterior: só marcar como "Pronto" se o HTML extraído realmente contiver <html no início e </html> no fim.
Considerar streaming: para respostas longas (acima de ~16k tokens), a recomendação da própria Anthropic é usar streaming em vez de chamada síncrona simples, para evitar timeout da requisição em si (problema parecido, mas na camada de rede/timeout, não só de max_tokens).


Teste de validação


Gerar um site de teste com conteúdo robusto (várias seções, como o de SDR com IA usado no teste anterior).
Conferir no log do backend o stop_reason retornado pela API.
Confirmar que o HTML final contém </html> de fechamento e que o preview renderiza completo.
Se possível, forçar um cenário onde o conteúdo pedido é maior que o max_tokens configurado, e confirmar que o sistema não marca como "Pronto" nesse caso — deve dar erro claro ou tentar de novo, nunca silenciosamente travar em branco.
