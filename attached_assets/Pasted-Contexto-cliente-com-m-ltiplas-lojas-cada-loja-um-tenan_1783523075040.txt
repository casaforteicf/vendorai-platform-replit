Contexto: cliente com múltiplas lojas, cada loja é um tenant separado (isolamento correto, mantém). Falta um papel de "administrador da rede" que enxerga as lojas de forma consolidada e/ou alterna entre elas sem logout — hoje cada tenant é uma ilha própria, sem conceito de agrupamento.
Schema (base para as duas fases):
Nova tabela: organizacoes
- id
- nome (ex: "Rede Materiais São José")
- ownerId (FK → users)

tenants (1 campo novo)
- organizacaoId (FK → organizacoes, nullable — só preenchido 
  quando o tenant faz parte de um grupo)

Nova tabela: usuarios_organizacao
- userId (FK → users)
- organizacaoId (FK → organizacoes)
- nivel: "admin_organizacao"

Fase A — Painel consolidado (baixo risco, implementar primeiro)
Não mexe em autenticação/sessão. Cada loja continua com login próprio, como hoje.
Implementação:
Tela nova que consulta os endpoints de métricas já existentes, uma vez por tenant dentro da mesma organizacaoId, de forma isolada (mesma segregação de hoje, nenhuma query cruza tenants no banco).
Soma/agrega os resultados só na camada de visualização (faturamento total, leads totais, negócios fechados totais, comparativo entre lojas).
Nunca expõe registro individual de uma loja na sessão de outra — só números agregados.
Teste antes de avançar: confirmar que os números batem com a soma manual de cada loja individualmente, e que nenhuma query do painel consolidado vaza dado bruto entre tenants.

Fase B — Troca de loja sem logout 
Implementação, com cuidados obrigatórios:
Seletor de loja no topo da tela, reemitindo sessão/token escopado para o tenantId escolhido.
Toda troca de loja valida explicitamente contra usuarios_organizacao se o usuário pertence àquela organização/tenant — nunca inferir a partir de sessão anterior.
Teste automatizado obrigatório antes de liberar: casos de teste que tentam forçar acesso cruzado (usuário da Loja A tentando ver dado da Loja B) e confirmam que sempre falha.
Implementar isolado, revisar e testar sozinho antes de misturar com qualquer outro bloco — facilita reverter se algo sair errado.
