# Briefing — Melhorar geração de imagens do Content Studio (Instagram)

Colar cada passo separadamente no Replit Agent, na ordem abaixo. Testar cada um antes de avançar.

---

## Passo 0 — Contexto para o Agent (não implementar nada ainda)

O módulo Instagram Content Studio hoje gera imagens usando DALL-E, com uma prompt genérica + um `BRAND_STYLE_BLOCK` fixo de marca. Problema: as imagens saem com "cara de IA genérica" e não têm relação visual com o negócio real do tenant (segmento, produto, ambiente).

Objetivo desta sessão: trocar o motor de imagem para Flux (Replicate) — mais fotorrealista, já validado no módulo Arch/Render — e injetar um bloco de estilo visual específico por vertical/segmento do tenant, além do bloco de marca já existente.

Não alterar nada neste passo, é só leitura de contexto.

---

## Passo 1 — Trocar motor de imagem: DALL-E → Flux

No endpoint que hoje gera as imagens do Content Studio (`/api/content-studio/generate` ou equivalente):

1. Localizar a chamada atual à API da OpenAI (DALL-E) usada para gerar a imagem do post.
2. Substituir pela chamada ao Replicate, modelo `black-forest-labs/flux-1.1-pro`:
   - Input: `prompt` (texto montado), `aspect_ratio` (conforme formato Feed/Stories já implementado), `output_format: "jpg"`, `prompt_upsampling: true`.
   - Usar o mesmo padrão de chamada assíncrona (`predictions.create` + polling) já usado no módulo Arch/Render — reaproveitar a função utilitária de chamada ao Replicate se já existir, para não duplicar código.
3. Manter a persistência do resultado (`image_url`) na tabela de gerações do Content Studio, sem mudar o schema.
4. Não mexer ainda na montagem do prompt (isso é o Passo 2) — só trocar o motor mantendo o prompt atual.
5. Testar: gerar 1 imagem de post real e comparar qualidade visual com uma gerada antes via DALL-E.

---

## Passo 2 — Bloco de estilo visual por vertical

Hoje existe `BRAND_STYLE_BLOCK` (identidade da marca do tenant) injetado no prompt. Adicionar um segundo bloco, `SEGMENT_STYLE_BLOCK`, baseado no segmento/nicho do tenant (mesmo campo usado no Prospector: Setor > Nicho > Subnicho).

1. Criar um objeto/mapa de estilos por segmento, cobrindo pelo menos os segmentos já ativos e os quick-wins: Construção Civil, Arquitetura/Design, Saúde/Beleza, Marcenarias, Imobiliárias, Distribuidoras/Autopeças, Academias.
2. Cada entrada do mapa deve descrever, em inglês (padrão já usado nos prompts de imagem): tipo de ambiente/cenário típico, paleta de cores predominante do setor, tipo de iluminação, e um adjetivo de mood (ex: "clean and technical" para autopeças, "warm and residential" para marcenaria, "clinical and bright" para saúde).
3. Buscar o segmento do tenant a partir do campo já existente no perfil/onboarding (o mesmo usado pelo Prospector). Se o tenant não tiver segmento definido, usar um bloco genérico neutro de fallback.
4. Montar o prompt final concatenando: `SEGMENT_STYLE_BLOCK` + tema do post (já preenchido pelo usuário) + `BRAND_STYLE_BLOCK` (cores/identidade do tenant) + especificações técnicas de formato (aspect ratio, já implementado).
5. Regra: `SEGMENT_STYLE_BLOCK` define o cenário/ambiente, `BRAND_STYLE_BLOCK` define cor e identidade — não deixar os dois brigarem por controle da mesma coisa (ex: os dois tentando definir paleta de cor). Cor final = sempre a da marca do tenant.
6. Testar: gerar posts para 2 tenants de segmentos diferentes (ex: um de Autopeças, um de Marcenaria) e confirmar que o cenário muda mas a identidade de marca (cores) se mantém.

---

## Passo 3 — Teste de validação com dados reais

1. Gerar 3 imagens de teste: um tenant do segmento Construção Civil, um de Saúde/Beleza, um de Autopeças.
2. Conferir: (a) ambiente/cenário condizente com o segmento, (b) cores de marca do tenant presentes, (c) qualidade fotográfica sem artefatos típicos de IA (mãos estranhas, texto ilegível, proporções erradas).
3. Reportar prints das 3 imagens para ajuste fino de algum bloco de estilo, se necessário.

---

## Passo 4 — Upload de foto real do produto/ambiente (image-to-image)

Permitir que o tenant suba uma foto real (produto, vitrine, ambiente, fachada) e usar essa foto como base da geração, em vez de criar a cena do zero. Mesmo princípio de preservação já validado no Arch/Render, aplicado aqui a foto real em vez de sketch 3D.

**1. Schema (Drizzle):**
Se a tabela `content_studio_uploads` já existir (do módulo de formato Feed/Stories/Reels), reaproveitar e adicionar ao enum `purpose` o valor `product_reference`. Se não existir ainda, criar:
- `content_studio_uploads` (id, tenant_id, session_id, file_url, purpose enum: `style_reference` | `post_material` | `product_reference`, created_at)

**2. UI — novo campo no formulário do Content Studio:**
1. Adicionar campo opcional "Foto real do produto/ambiente (opcional)" — upload único por geração, JPG/PNG/WebP, até 10MB.
2. Quando uma foto for enviada, mostrar um toggle: "Manter este produto/ambiente exatamente como está" (ligado por padrão) vs "Usar só como inspiração de estilo".
3. Se o toggle estiver desligado, a foto entra como referência solta (comportamento atual do `style_reference`, sem preservação rígida).

**3. Backend — lógica de geração condicional:**
1. Se houver foto com `purpose: product_reference` e toggle de preservação ligado:
   - Trocar o motor de `flux-1.1-pro` para `flux-kontext-pro` (image-to-image), passando a foto enviada como `input_image`.
   - Montar o prompt com hierarquia de preservação em duas camadas (mesmo princípio do Arch/Render): **produto/objeto principal da foto = trava absoluta** (não alterar forma, cor, texto, logo, proporções); **cenário ao redor (fundo, iluminação, composição, elementos de apoio) = livre para reinterpretar** conforme o `SEGMENT_STYLE_BLOCK` e `BRAND_STYLE_BLOCK` do Passo 2.
   - Exemplo de estrutura do prompt (em inglês, padrão já usado): abrir com "Keep the main product/subject in this photo exactly as shown — same shape, color, text, logo and proportions. Reimagine only the background and surrounding scene as: [SEGMENT_STYLE_BLOCK + BRAND_STYLE_BLOCK]. Professional product photography lighting, no distortion of the original object."
   - Aplicar a mesma regra de disciplina de correção única por geração validada no Arch/Render: não empilhar múltiplos ajustes de cenário na mesma chamada — se o resultado precisar de correção, fazer como ajuste sequencial separado sobre a imagem já gerada, nunca combinado com o prompt base.
2. Se não houver foto de referência, manter o fluxo do Passo 1/2 (geração 100% a partir do prompt).

**4. Teste:**
1. Testar com uma foto real de produto de um tenant (ex: uma peça de autopeças ou um móvel planejado).
2. Confirmar que o produto na imagem final é reconhecível e fiel ao original, e que só o cenário ao redor mudou conforme o estilo do segmento/marca.
3. Testar também o caminho sem preservação (toggle desligado) para confirmar que o comportamento de "inspiração livre" continua funcionando.

---

## Passo 5 — Teste final combinado

1. Gerar um post completo usando: foto real de produto + `SEGMENT_STYLE_BLOCK` do tenant + `BRAND_STYLE_BLOCK` + formato Feed ou Stories já escolhido.
2. Validar ponta a ponta com 2 tenants de segmentos diferentes.
3. Reportar prints finais. Esse é o critério de "pronto" do briefing.
