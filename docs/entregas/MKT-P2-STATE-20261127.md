# MKT-P2-STATE — Máquina de estados da peça (Fase 2)

Data: 2026-11-27
Branch: `feat/mkt-piece-state-machine` (base `main` @ ec2f36564)
Origem: Fase 2 do `docs/ux/PLANO-MELHORIA.md` (PR #3771), alinhada ao ALINHA-01.

## Objetivo
Dar à peça **um estado único com transições validadas**, sem criar um vocabulário
paralelo ao que o ALINHA-01 já mergeou (`deriveOperationalState`).

## Entregue (contrato puro em `lib/vendor-brain`)

1. **`PieceMediaState`** — `pending | processing | ready | failed`
   - derivado de status do calendário, geração, vídeo final, materialização e publicação.
   - peça estática sem imagem = `pending`; vídeo `gerado` sem MP4 = `processing`.
2. **`PieceAction`** — ação/CTA por estado, com `enabled` e `reason`.
   - exemplos: `planned → release`, `authorized → produce`, `in_review` só aprova com
     mídia `ready`; `failed → retry`; `published → view_results`.
3. **Matriz de transições** — `PIECE_TRANSITIONS`, `canTransitionPiece`, `transitionPiece`
   - erro estável `INVALID_PIECE_TRANSITION:from->to` para a API responder 422.
4. **14 testes novos** cobrindo mídia, ação e transições (válidas e inválidas).

## Decisões
- O vocabulário canônico é o **já existente** (`planned`, `authorized`, `producing`,
  `in_review`, `approved`, `scheduled`, `published`, `rejected`, `skipped`, `failed`).
- `media` é ortogonal ao estado: a etapa não muda porque a mídia falhou; a ação muda.
- Nada de escrita direta de status: a API deve chamar `transitionPiece`.
