# AB-05 — Tela de mapeamento (de-para) produto → insumo

| Campo | Valor |
|---|---|
| Identificador | AB-05 |
| Nome | Tela de de-para entre o catálogo de estoque e os insumos do A&B |
| Versão | 1.0 |
| Data de atualização | 2026-11-03 |
| Estado | **Implementado e validado por teste/`tsc`**. Não exercitado contra banco. |

## Objetivo

Dar ao gerente a tela que popula `ab_insumo_produto` — o mapa criado no AB-04. Sem ele o job de
sincronização reporta **todos** os produtos como `produtosSemMapa` e nenhum saldo chega em
`ab_estoque_saldos`, então o motor preditivo não tem o que prever.

## O que a tela faz

1. Lista os produtos do catálogo antigo (mock) com saldo e unidade de estoque.
2. Para cada produto, o usuário escolhe o **insumo correspondente** (lista real, `GET /ab/insumos`)
   e digita o **fator de embalagem** quando a unidade não é métrica.
3. **Salvar** faz `POST /ab/insumo-produto` (upsert por produto), recarrega os mapeamentos e marca a
   linha; **Desvincular** faz `DELETE`.
4. O contador no topo mostra "N de M mapeados".

## Decisões

1. **Catálogo antigo é mock, gravação é real.** Não existe endpoint de produtos do estoque
   (`hotel_stock_location_balances` não tem schema Drizzle nem rota). A constante
   `PRODUTOS_ESTOQUE_MOCK` tem 4 produtos com ids em formato UUID, para a troca pela API ser
   só substituir a fonte. Insumos e gravação são reais: uma tela que "salva" num mock não
   provaria nada.
2. **O fator é bloqueado na tela quando a unidade não é métrica** (saco, caixa, fardo) e o
   backend recusaria de qualquer forma. O aviso é o mesmo do job: converter sem fator some com o
   saldo, e é o tipo de erro que só aparece quando falta mercadoria.
3. **Upsert por produto.** A unique é `(tenant_id, produto_catalogo_id)`; reenviar a mesma linha
   troca insumo/fator em vez de duplicar — é o que a tela precisa ao "corrigir" um de-para.
4. **A tela lista insumos, não `ab_estoque_saldos`.** O alvo do mapa é o insumo (catálogo); o
   saldo é consequência do sync. Listar saldos confundiria "insumo que ainda não tem saldo" com
   "insumo inexistente".

Os 7 testes cobrem: lista + contador, select com insumos da API, recusa sem insumo, recusa saco
sem fator, gravação com fator (payload correto), métrica sem fator (payload `null`) e
pré-preenchimento de mapeamento existente.

## Pendências

1. **Produtos reais**: trocar `PRODUTOS_ESTOQUE_MOCK` por um `GET /ab/produtos-estoque` quando
   houver rotas para `inventory_items`/`hotel_stock_location_balances`.
2. **Nada foi executado contra banco** — migration 20261104 e endpoints validados por teste/`tsc`.
3. O vínculo salvo com um produto mock **não** vai encontrar o produto no banco (FK de
   `produtos_catalogo`): a tela mostra o erro da API. Isso é esperado e some quando a fonte de
   produtos for real.
