# VendorAI AI Orchestrator V2

## Goal

Use specialized models behind the existing multi-tenant AI Gateway while reserving the strongest reasoning tier for user-visible premium creation.

## Routing policy

| Workload | Default model |
|---|---|
| Campaign strategy and creative briefing | `gpt-6-astra` |
| Ads strategy and primary creative copy | `gpt-6-astra` |
| Full site and landing-page generation | `gpt-6-astra` |
| Primary content creation | `gpt-6-astra` |
| Video script and creative direction | `gpt-6-astra` |
| Render/image prompt and creative direction | `gpt-6-astra` |
| Strategic intelligence | `gpt-6-astra` |
| Proposals, media interpretation and professional support | `gpt-5.6-sol` |
| General operational work | `gpt-5.6-terra` |
| SDR, closer, follow-up and conversational agents | `gpt-5.6-luna` |
| Extraction and high-volume work | `gpt-5.6-luna` |
| Premium image composition | `gpt-image-2` |
| Fast image composition | `gpt-image-1-mini` |
| Video composition | VendorAI Media Workspace |

Campaigns and ads currently reach the router through `briefing_generator`, `spin_briefing` and `content_generator`. Sites and landing pages use `site_generator`. Image/render direction may use `image_generator`, but final pixels are generated by the image-model router rather than by the text model. Video uses Astra as creative director and the media workspace as composer.

## Premium creation principle

The system optimizes cost in invisible operational work, not in the main creative deliverable. User-visible premium outputs should therefore prefer Astra for planning, reasoning, copy, structure and review, while specialized media models remain responsible for image and video composition.

## Safe rollout

The router is disabled by default. Enable only in a non-production environment or approved pilot tenant deployment:

```env
VENDORAI_AI_ROUTER_V2=true
VENDORAI_AI_ROUTER_TENANTS=<tenant-id-interno>
VENDORAI_MODEL_ASTRA=gpt-6-astra
VENDORAI_MODEL_SOL=gpt-5.6-sol
VENDORAI_MODEL_TERRA=gpt-5.6-terra
VENDORAI_MODEL_LUNA=gpt-5.6-luna
VENDORAI_IMAGE_MODEL_PREMIUM=gpt-image-2
VENDORAI_IMAGE_MODEL_FAST=gpt-image-1-mini
```

The router fails closed when the tenant allowlist is empty. Use a comma-separated list of tenant IDs; `*` is reserved for a deliberately approved global rollout.

Explicit model choices made by existing callers always win. Disabling `VENDORAI_AI_ROUTER_V2` immediately restores the legacy `gpt-4o-mini` default without a deployment rollback.

## Rollout order

1. CI and typecheck.
2. Staging smoke tests for JSON output and quota logging.
3. One internal VendorAI tenant as pilot.
4. Measure quality, latency and cost per feature.
5. Enable approved premium workloads for selected tenants.
6. Connect premium image and video composition after their storage/output adapters pass integration tests.
7. Expand the allowlist only after cost and quality telemetry is healthy.

## Guardrails

- No database migration.
- No frontend route change.
- No automatic production activation.
- BYOK, quotas, daily ceiling, usage logs and Anthropic fallback remain in the central gateway.
- Modern reasoning models do not receive legacy `temperature` or `max_tokens` parameters.
- Operational transformations such as tags, extraction, classification and simple summaries must not be promoted to Astra merely because they support a premium workflow.
